# Contributing to Bloom Proof

## The artifact rule

Every entry must include a working artifact: a repo, a live demo, or an open dataset. It must load and work when the reviewer clicks it.

No working artifact, no entry. Takes don't ship.

## How to add an entry

1. Copy `entries/template.md` to `entries/NNN-your-entry-name.md` (use the next available number).
2. Fill in every section: Problem, Solution, Artifact, Human, License.
3. Open a pull request.

## PR checklist

Your PR is reviewed against this checklist. Missing any item? It gets closed with the checklist pasted back — no hard feelings, fix it and reopen.

- [ ] Real problem stated (a human's problem, one paragraph)
- [ ] Solution described in plain language
- [ ] Artifact linked and working (repo, demo, or dataset — the reviewer will click it)
- [ ] Artifact is openly licensed (MIT, Apache-2.0, CC BY-SA 4.0, CC0, or similar)
- [ ] Human helped is named (their words if possible)

## What gets rejected

- Vaporware: announcements, roadmaps, "coming soon"
- Closed source: if the artifact isn't open, it's not an entry
- Marketing: entries document real help, not product launches

## Review process

Maintainers review PRs in the open. Discussion happens on the PR. Merges are fast when the checklist is clean.
